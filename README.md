# AI Media OS — مركز التحكم ومنشئ الشركة

يُكمل هذا المستودع لوحة AI Media OS الحالية ولا يعيد بناءها من الصفر. الواجهة عربية RTL ومتجاوبة؛ الخلفية REST مبنية على Python القياسي مع تبعية `cryptography` لخزنة المفاتيح، والتخزين المحلي SQLite.

## ما أُنجز في المرحلة الثانية

- **Company Builder فعلي** داخل لوحة المالك، بواجهات لإدارة الأقسام، المديرين وموظفي AI والعاملين، الهيكل التنظيمي، الأدوار والصلاحيات، سير العمل، سجل الأدوات، ومصادر المعرفة.
- CRUD للأقسام والموظفين والأدوار المخصصة؛ حماية الحذف عند وجود مراجع، ومنع روابط المدير أو الموظف الأعلى من عبور الأقسام أو تكوين دورات.
- ملفات موظفين بتبويبات للوظيفة، إعداد AI، الأدوات، صلاحيات الوحدات، الصلاحيات، المعرفة، المهام والنشاط؛ مع إيقاف/تفعيل وتغيير المدير وتكليف الموظف بمهمة.
- اختيار المشروع والأولوية والموعد واشتراط الموافقة عند إنشاء مهمة من ملف الموظف. المهمة مرتبطة بموظف AI وبالمشروع الفعلي في SQLite.
- وصول الموظفين إلى وحدات النظام والأدوات ومصادر المعرفة يُحفظ في جداول علاقات منفصلة. الوحدات الإدارية الحساسة مثل الأمان والإعدادات ومنشئ الشركة غير قابلة للتعيين لموظف AI.
- تجربة AI من الملف تمر بفحص صلاحية `USE_AI_MODEL`، وتستخدم فقط مصادر المعرفة الممنوحة لذلك الموظف، ثم تستدعي نقطة Chat Completions الحقيقية لموجّه OpenAI-compatible على الخادم. إذا لم يتوفر الإعداد، تُرجع الواجهة حالة خطأ صريحة ولا تصطنع جواباً.
- أدوات وسير عمل ومصادر معرفة قابلة للتعريف من اللوحة. سير العمل في هذه المرحلة **تعريف وخطوات محفوظة فقط**؛ لا يطلق إنتاجاً تلقائياً أو إجراءات خارجية.
- سجل النشاط يسجل تغييرات Company Builder والمهام ونتيجة اختبار النموذج دون تخزين نص prompt أو استجابة AI أو مفاتيح اعتماد.
- الصفحة الرئيسية وملخص Company Builder يعرضان إحصاءات مشتقة من قاعدة البيانات، لا أرقاماً ثابتة. بيانات البداية تُنشأ اختيارياً فقط بأمر seed المتكرر بأمان.
- يبقى **Manus محرك التطوير/التنفيذ الخارجي**، لا يُنشأ كموظف AI داخل الشركة.

## التشغيل والبناء

يتطلب Python 3.11+ وNode.js، ولا توجد حزم JavaScript خارجية. لتثبيت تبعية تشفير مفاتيح التكاملات:

```bash
cp .env.example .env
python3 -m pip install -r requirements.txt
python3 scripts/init_vault.py
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

ضع الرمز المولّد في `OWNER_API_TOKEN` داخل `.env`، ثم:

```bash
pnpm build       # ينسخ الأصول المتحققة إلى dist/
pnpm test        # اختبارات API والانحدار
pnpm start       # الخادم على HOST=127.0.0.1 وPORT=8080 افتراضياً
```

يمكن أيضاً استخدام `python3 -m backend.server`. إذا وُجد `dist/index.html` يقدّم الخادم الملفات المسموح بها من `dist/`؛ تظل قاعدة البيانات وملف البيئة في جذر المشروع. المتغيرات `HOST` و`PORT` و`AI_MEDIA_DB_PATH` و`AI_MEDIA_STATIC_ROOT` قابلة للضبط. لا تعرّض الخادم للإنترنت دون TLS وحدود وصول وتشغيل دائم مناسبين.

افتح `http://127.0.0.1:8080` وسجّل الدخول كمالك. يُحفظ الرمز في `sessionStorage` للجلسة فقط. عند غياب `OWNER_API_TOKEN` تبقى الصحة العامة متاحة وتُغلق كل مسارات الشركة الخاصة.

### بيانات البداية الاختيارية

لا يُنشئ تشغيل الخادم بيانات إنتاجية تلقائياً. للمعاينة أو التطوير فقط، نفّذ:

```bash
python3 -m backend.seed
```

أمر seed قابل لإعادة التشغيل ولا يكرر العناصر. لا تضف قاعدة SQLite أو `.env` إلى Git.

## إعدادات الأنظمة الخارجية

تُخزن الأسرار في بيئة الخادم أو `.env` فقط، ولا تُضمّن في `dist/` أو المتصفح أو Git أو سجل النشاط. يتحقق الخادم فعلياً من اتصال النظام قبل أن يعرض `ONLINE`.

- **AI Router:** `AI_ROUTER_BASE_URL` و`AI_ROUTER_API_KEY`، واختيارياً `AI_ROUTER_MODEL` أو `AI_ROUTER_CHAT_COMPLETIONS_URL`. يقبل أيضاً إعداد `OPENAI_API_BASE` و`OPENAI_API_KEY` المتوافق القديم. يُفحص `/models` وتُستدعى `/chat/completions` عند اختبار موظف.
- **Manus:** `MANUS_API_KEY` أو `MANUS_API_TOKEN`، مع فحص محدود عبر `GET /v2/task.list?limit=1`. لا تُعرض الحالة متصلة دون مفتاح صالح واستجابة ناجحة؛ إدارة الشركة لا تستخدم Manus كموظف داخلي.
- **GitHub:** اعتماد مضيف `gh` عند تفعيل `GITHUB_USE_CLI=true`، أو `GITHUB_TOKEN` و`GITHUB_HEALTH_URL`. سحب/دفع المستودع أثناء التطوير لا يعني تلقائياً أن تكامل التطبيق نفسه متصل.
- **فحوص اختيارية أخرى:** `AI_ROUTER_HEALTH_URL` و`MANUS_HEALTH_URL` و`GITHUB_HEALTH_URL` و`EXTERNAL_HEALTH_URLS`.

لا تضع رموز الاعتماد داخل أوصاف الأدوات أو مصادر المعرفة أو prompts. طلبات الكتابة تفحص أنماط الأسرار الشائعة وترفض المحتوى المطابق.

## قاعدة البيانات

يبني الخادم على مخطط SQLite القائم ولا يستبدل جداول المرحلة الأولى. أُضيفت أو وُسّعت كيانات الأقسام وموظفي AI، الأدوار والصلاحيات ومنح الموظف، أدوات الموظفين، مصادر المعرفة ومنح الوصول، الوحدات المعينة، مسارات العمل وخطواتها، علاقات الهيكل، وربط المهام بالموظف والمشروع والموعد ومتطلب الموافقة. توجد مفاتيح خارجية وفهارس للعلاقات والاستعلامات، ومهاجرات قابلة للتكرار للجداول السابقة.

جداول علاقات أساسية:

- `organization_relationships`: المدير والموظف الأعلى، مع منع الذات والدورات والتحقق من القسم في الخلفية.
- `employee_permissions` و`employee_tools` و`employee_knowledge_access` و`employee_modules`: منح منفصلة قابلة للتحقق، ولا يستطيع الموظف منح نفسه صلاحيات.
- `workflow_steps`: ترتيب ثابت وخطوات مرتبطة بمسار.
- `tasks`: حقول ربط الموظف والمشروع والموعد والموافقة أُضيفت إلى الجدول الموجود.

الوصول إلى API خاص يتطلب `X-Owner-Token`. هذه نسخة بمالك واحد؛ الأدوار المسندة إلى موظفي AI هي بيانات تفويض تستخدمها مسارات الموظفين، وليست نظام حسابات مستخدمين متعددين. جميع تغييرات الإدارة تنفذ تحت جلسة المالك.

## واجهات API المضافة

كل المسارات التالية، باستثناء فحوص الصحة وكتالوج الوحدات، تتطلب رمز المالك:

| المسار | الوظيفة |
|---|---|
| `/api/departments` | قراءة وإنشاء الأقسام؛ `PATCH` و`DELETE` على `/api/departments/{id}` |
| `/api/ai-employees` | قراءة وإنشاء المديرين والموظفين والعاملين؛ `PATCH` و`DELETE` على `/api/ai-employees/{id}` |
| `/api/ai-employees/{id}` | ملف الموظف والمهام والنشاط والموارد الممنوحة؛ يدعم `PATCH` تعديل الصلاحيات وروابط الوحدة |
| `/api/ai-employees/{id}/permissions` | استبدال منح الصلاحيات بعد التحقق منها |
| `/api/ai-employees/{id}/test` | التحقق من الصلاحية، جمع المعرفة الممنوحة، ثم استدعاء Router حقيقي |
| `/api/ai-employees/{id}/tasks` | إنشاء مهمة مرتبطة بموظف ومشروع اختياري |
| `/api/company/structure` | شجرة الأقسام والموظفين من روابط SQLite الفعلية |
| `/api/roles` | قراءة وإنشاء دور؛ `/api/roles/{id}` لتعديل القالب أو حذفه مع حواجز الاستخدام |
| `/api/permissions` | كتالوج الصلاحيات وعلامات الحساسية |
| `/api/tools` | قراءة سجل الأدوات وإضافة أداة؛ المعينون ظاهرون عبر منح ملف الموظف |
| `/api/knowledge-sources` | قراءة الفهرس وإنشاء مصدر؛ محتوى المعرفة لا يظهر في الفهرس أو الملف |
| `/api/workflows` | قراءة وإنشاء تعريفات وخطوات سير العمل |
| `/api/external-integrations/pipeline` | توليد ElevenLabs ثم مهمة Kling غير متزامنة ثم دمج MP4 محلياً؛ استجابة المالك تتضمن حسابات موقوفة عند التدوير |
| `/api/external-integrations/generate/audio` و`/generate/video` | توليد صوت أو فيديو منفصل عند الحاجة |
| `/api/external-integrations/generations/{id}` | استعلام حالة Kling؛ يكتمل الدمج النهائي عند نجاح المهمة |
| `/api/external-integrations/generations/{id}/audio` و`/media` | بث ملفات الصوت والـ MP4 المحمية برمز المالك |
| `/api/dashboard` و`/api/company-builder/summary` | مؤشرات حية مصدرها قاعدة البيانات |
| `/api/modules` | كتالوج عام للوحدات وحقل يميز الوحدات التي يمكن منحها لموظف AI |

## الاختبارات والتحقق

```bash
python3 -m compileall -q backend tests
for file in frontend/*.js; do node --check --input-type=module < "$file"; done
pnpm build
pnpm test
```

تغطي الاختبارات استمرار المرحلة الأولى، المصادقة، الأقسام والعلاقات والهيكل، الدورة/القسم غير الصالح، الملفات والتوقف وإعادة التفعيل، الأدوار والصلاحيات، روابط الوحدات والأدوات والمعرفة، حماية الأسرار، مهام الموظفين وربط المشروع وسجل نشاط ملف الموظف، سير العمل، Router، حسابات الوسائط، تدوير 429، وحماية endpoints. اختبارات المزود تستخدم استجابات وهمية معزولة؛ لا تستدعي نموذجاً أو API مدفوعاً أثناء suite. يُختبر دمج FFmpeg محلياً بمقاطع اصطناعية قصيرة، لا بمحتوى أو اعتماد إنتاجي. اختُبرت أيضاً التدفقات الأساسية في Chromium على قاعدة بيانات مؤقتة مستقلة، وعُرضت صفحة الفريق عند عرض هاتف 390×844 دون تجاوز أفقي للصفحة.

## الحدود الحالية / غير المهيأ

- لا يوجد حساب مستخدم متعدد أو RBAC لمشغلي بشر متعددين؛ المالك هو المنفذ الوحيد لعمليات الكتابة.
- سجل الأدوات تعريف آمن فقط: لا ينفذ الأدوات أو تكاملات Manus/GitHub من قِبل الموظف بعد.
- سير العمل محفوظ، لكنه لا ينفذ الأتمتة أو مراحل إنتاج المحتوى.
- ملفات المشاريع والشخصيات تقرأ من مخطط المرحلة الأولى، لكن عمليات CRUD لها خارج Company Builder.
- ملفات المعرفة تُخزن محلياً في SQLite في هذه المرحلة؛ فهرسها لا يكشف محتواها، ويُرسل المحتوى إلى AI Router فقط في سياق اختبار موظف مُصرّح له.
- اتصال Manus/GitHub/AI Router يعتمد على اعتمادات بيئة صحيحة؛ لا تعلن الواجهة اتصالاً ناجحاً لمجرد وجود سجل أو قيمة غير صالحة.

لا يبدأ هذا العمل أي مرحلة أو وحدة إنتاج كبرى أخرى قبل اعتماد المالك لهذه المرحلة.


## التكاملات الخارجية ومجموعة حسابات الوسائط

توفر وحدة **التكاملات الخارجية** إدارة حتى 20 حساباً لخدمات الفيديو والصوت، مع حسابات نشطة أو متوقفة وتدوير Round-robin منفصل لكل مزود وخدمة. تحفظ بيانات الحساب ومفتاح API المشفر في جداول SQLite منفصلة؛ المفتاح لا يعود من أي API ولا يدخل سجل النشاط. يُستخدم `AI_MEDIA_VAULT_KEY` (Fernet) من بيئة الخادم لتشفير المفاتيح. في نسخة محلية جديدة، أنشئ أو تحقق من المفتاح دون طباعته عبر `python3 scripts/init_vault.py` بعد نسخ `.env.example` إلى `.env`؛ الملف `.env` مستثنى من Git ويُحفظ بصلاحية 0600. لا تغيّر مفتاح الخزنة بعد حفظ حسابات، وإلا لن يمكن فك تشفيرها.

تدعم الوحدة الآن طلبات توليد فعلية عند إرسال المالك نموذج **إنشاء صوت + فيديو**: يولّد ElevenLabs الصوت أولاً، ثم يرسل Kling 3.0 Text-to-Video مهمة غير متزامنة، ثم يدمج الخادم الصوت مع الفيديو عبر FFmpeg عند اكتمال Kling. واجهة Kling Text-to-Video لا تقبل `audioUrl` خارجياً؛ الدمج يتم محلياً وليس عبر حقل مزود، ولا توجد مزامنة شفاه تلقائية. إذا كان الصوت أطول من مقطع Kling، يمدد الدمج الإطار الأخير الثابت حتى نهاية الصوت.

عند HTTP 429/خطأ معدل أو نفاد رصيد/حزمة صريح، أو رفض اعتماد 401/403، يُحدّث الحساب إلى `PAUSED` في SQLite وتُحفظ علة الإيقاف؛ يحاول النظام كل حساب نشط آخر مرة واحدة كحد أقصى في الطلب نفسه، ويعيد قائمة الحسابات الموقوفة للواجهة. يستفيد HTTP 429 من `Retry-After` (وبديل 60 ثانية)، ويُعاد تنشيط الحساب تلقائياً بعد انتهاء هذه المهلة عند أول محاولة تدوير لاحقة. حسابات الرصيد أو الاعتماد المرفوض تبقى متوقفة حتى مراجعتها وإعادة تفعيلها يدوياً. أخطاء الشبكة أو مدخلات المزود لا تؤدي إلى إعادة إرسال الطلب تلقائياً لأن نتيجة الطلب قد تكون غير مؤكدة.

النقاط التنفيذية تتطلب رمز المالك: `POST /api/external-integrations/pipeline` لبدء الأنبوب؛ `POST /api/external-integrations/generate/audio` أو `/generate/video` للتوليد المنفصل؛ `GET /api/external-integrations/generations/{id}` لفحص مهمة Kling؛ و`GET /api/external-integrations/generations/{id}/audio` أو `/media` لتدفق ملف محفوظ. ملفات MP3 وMP4 محفوظة بجوار ملف SQLite داخل `generated_media/` بصلاحيات مقيدة، والمجلد مستثنى من Git. رابط Kling نفسه مؤقت (حتى 30 يوماً)؛ الملف النهائي المحلي لا يعتمد عليه بعد تنزيله.

قاعدة SQLite الحالية محلية داخل Sandbox؛ بياناتها ومفاتيحها وملفات الوسائط ليست قاعدة إنتاج دائمة. لا تُدخل مفاتيح إنتاج حقيقية في نسخة معاينة مؤقتة قبل اكتمال الاستضافة الدائمة وترحيل البيانات.
